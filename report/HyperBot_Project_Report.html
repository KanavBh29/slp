1. Abstract

HyperBot is a publicly hosted, voice-enabled chatbot that answers questions about 35 supercars and hypercars: their details, specifications, prices and where to buy them. The user's speech is transcribed in the browser by the Web Speech API, or by an on-device Whisper model when the browser's speech service is unavailable. Car names, brands and budgets are extracted with exact, fuzzy and phonetic matching, and replaced by placeholder tokens. A Bidirectional LSTM initialised with pre-trained GloVe embeddings then classifies the sentence into one of 26 intents. A dialogue manager with context memory and slot filling builds the answer from a curated knowledge base, shows it next to the recognised speech, and reads it aloud.

The model was trained on a hand-built corpus of 796 utterance templates, augmented to 4,158 sentences. In 5-fold cross-validation on phrasings never seen during training, it reaches 81.5% ± 3.3 accuracy. That is 4.5 points above the same network trained without transfer learning, and on par with a bag-of-words MLP baseline that is twice its size. On the in-distribution random split it reaches 95.4%. The whole system runs client-side and is deployed to GitHub Pages by a CI pipeline that runs end-to-end tests before every release.

2. Introduction & objectives

Car enthusiasts often want quick, specific answers ("How fast is the Koenigsegg Jesko?", "Where can I buy a McLaren 750S?") without searching through brochures and listings. A voice interface makes this natural, but it brings two NLP problems. First, speech recognisers often mishear exotic model names. Second, users phrase the same question in many different ways. The project objectives were to:

  1. accept voice input and convert it to text with a suitable speech recognition technique;
  2. classify the text with a deep-learning intent model and generate an appropriate response;
  3. display both the recognised speech and the chatbot response;
  4. deploy the application online with a public link; and
  5. document the dataset, architecture, methodology and results.

3. System architecture

The application is a static web app: HTML, CSS and JavaScript ES modules, a JSON knowledge base, and the exported model weights. The neural network is trained offline in Python with TensorFlow/Keras, and its weights are exported to a compact binary file. A hand-written JavaScript implementation of the forward pass runs inference in the browser. This design needs no server, has no API keys and no cold starts, and can be hosted free on GitHub Pages.

4. Speech recognition

General-purpose ASR is weakest on exactly the words this domain depends on: "Chiron" is heard as "sheeran", "Huayra" as "wire a", "Nevera" as "never a". Three mechanisms compensate:

  • n-best rescoring: a lower-ranked alternative is chosen if it is the only one that mentions a known car.
  • Fuzzy matching: windows of 1–3 words are matched to every alias by normalised Levenshtein similarity (≥ 0.8). Only windows containing an uncommon word are considered, to avoid false positives.
  • Phonetic matching: a simplified Metaphone key maps sheeran and chiron to the same key xrn, and hurricane and huracan to hrkn.

The recognised text and its ASR confidence are shown above each answer, so the user can always see what the system heard.

5. Dataset

5.1 Intent corpus

No public dataset exists for a supercar assistant, so a domain corpus was written by hand: 796 templates over 26 intents. It includes short follow-ups ("how much does it cost"), unpunctuated speech-style text and an out_of_scope class. Templates contain slot placeholders {car}, {brand} and {num}, which are delexicalised to the tokens xcar, xbrand and xnum. As a result, the network learns the intent rather than memorising car names, and new cars can be added without retraining.

Augmentation (12 variants per template):

  • polite prefixes and suffixes ("hey …", "… please");
  • unknown-entity simulation: 12% of car slots are filled with out-of-vocabulary tokens;
  • ASR word-dropout: one non-entity word is deleted with probability 0.15.

The final training set has 4,158 sentences.

6. Text preprocessing & entity extraction

  1. Normalisation: lowercase, remove apostrophes ("what's" → "whats"), replace punctuation with spaces while keeping decimals and model names such as "t.50".
  2. Entity extraction: car aliases are matched longest first (so "Bugatti Chiron" wins over "Bugatti"), then fuzzy and phonetic car matches, then brands. Matches are replaced by xcar or xbrand.
  3. Number masking: amounts such as "$2.5 million", "300k" and "2.5s" become xnum, while names like "V12" are kept. A separate parser converts budgets to USD, including spoken forms ("two million", "half a million", "five hundred thousand") and rupees ("3 crore").
  4. Encoding: tokens are mapped to vocabulary ids (1 = OOV) and post-padded to length 24.

The Python (training) and JavaScript (inference) preprocessors are tested against each other on tricky inputs to guarantee identical tokens.

Why a BiLSTM? Intent depends on word order and context, e.g. "is the xcar faster than the xcar" (compare) versus "fastest car" (ranking). A bidirectional LSTM reads the sentence in both directions and handles variable length through masking.

Why GloVe transfer learning? The vocabulary (8,116 words) contains every training word plus the 8,000 most frequent English words, all initialised with GloVe vectors. Words that never appear in training receive no gradient and keep their pre-trained meaning. This lets the model handle unseen wording, e.g. "where can I acquire one" → where_to_buy and "which vehicles are battery electric" → electric_hybrid. The placeholder tokens start from the vectors of "supercar", "manufacturer" and "million".

Training: Adam (learning rate 2·10-3), sparse categorical cross-entropy, batch size 32, up to 80 epochs, early stopping on validation loss (patience 12, best weights restored), 10% validation split, seed 42. The final model trained for 38 epochs and reached 98.8% validation accuracy.

Browser export: embeddings are quantised to int8 with a per-row scale, and the other weights stay float32, giving a ≈0.7 MB binary plus an 80 KB vocabulary. The JavaScript LSTM (Keras gate order i, f, c, o) reproduces the Keras probabilities to within 5·10-7.

8. Dialogue management

  • Confidence threshold (0.5): below it, rule-based fallbacks use the extracted entities (two cars → compare, one car → overview, a budget → recommendations). Otherwise the bot asks the user to rephrase.
  • Context memory: the most recent cars are remembered, so "How fast is it?", "Price please" and "Compare it with the Jesko" work. Context is reused only for genuine follow-ups (a pronoun or a very short question). "What is the price of the Tesla Roadster?" gets "I don't have that car" instead of a wrong answer.
  • Slot filling: "Recommend me a car" → "What is your budget?" → "500 thousand" → recommendations.
  • Response types: text answers, spec cards, comparison tables (winners highlighted), top-5 rankings (optionally per brand), budget lists, purchase links, and text-to-speech output.

10. Results & evaluation

10.1 Intent classification

Three neural models were compared under two protocols:

  • Random split (85/15 of the generated sentences, 3,547/626). This is in-distribution: test sentences can share a template with training sentences.
  • Template 5-fold cross-validation. Each fold holds out 20% of every intent's templates, so every test sentence is a phrasing the model has never seen. This is the more realistic estimate for new users.

Findings.
  • Transfer learning helps most on unseen phrasings. GloVe initialisation adds +4.5 accuracy points and +0.052 macro-F1 over the same BiLSTM trained from scratch.
  • On the in-distribution split, all models exceed 94%. The bag-of-words MLP is slightly ahead there because keyword memorisation works well when templates repeat.
  • On genuinely new phrasings, the GloVe-BiLSTM has the highest mean accuracy and F1. The gap to the baseline is within fold-to-fold variance, so the two are best described as comparable. The BiLSTM is less than half the size and also models word order.

Error analysis. Most remaining errors fall into four groups:

  • one-word slang with no embedding ("thx", "cya", "yo");
  • off-topic questions shaped like "who/what is X" ("who are the beatles" → car_overview);
  • a single car's acceleration confused with the acceleration ranking ("zero to sixty" → quickest_car);
  • overlap between availability and purchasing ("is it sold out" → where_to_buy).

The dialogue manager limits the impact of these errors. For example, a car-specific intent with no car mentioned produces a clarifying question rather than a wrong fact.

11. Application walkthrough

Using the application

  1. Open https://kanavbh29.github.io/slp/ in Chrome, Edge or Safari (HTTPS is required for the microphone).
  2. Tap the red microphone button and allow microphone access.
  3. Ask a question, for example "How much is the Ferrari F80?".
  4. The recognised speech appears in the chat, followed by the answer, which is also spoken aloud.
  5. Typing and the suggestion chips work as alternatives to voice.
  6. In browsers that block the cloud speech service (e.g. Brave), the app switches to on-device Whisper. Tap the mic once to start and again to stop.

12. Limitations & future work

  • The intent corpus is synthetic. Collecting real anonymised queries would give the largest robustness gain.
  • Web Speech API quality and privacy depend on the browser vendor. Whisper keeps audio on the device but needs a ~40 MB download.
  • Prices and availability change. The static JSON should be refreshed regularly or connected to a live listings API.
  • Possible extensions: a fine-tuned transformer encoder (e.g. DistilBERT) for intents; joint intent + slot tagging (BiLSTM-CRF) instead of dictionary matching; multilingual ASR; images of each car.

13. Conclusion

HyperBot meets all project requirements. It accepts voice input, transcribes it with a speech recognition engine (with an on-device fallback), classifies intent with a deep-learning BiLSTM using transfer-learned GloVe embeddings, and answers questions about details, specifications, prices and where to buy 35 supercars and hypercars. Each turn shows both the recognised speech and the response. The system is publicly deployed through an automated test-and-deploy pipeline. Evaluation on unseen phrasings shows a clear benefit from transfer learning (81.5% vs 77.0%). Domain-specific handling of speech recognition errors (n-best rescoring, fuzzy and phonetic matching) makes the voice experience reliable even for hard-to-pronounce car names.
